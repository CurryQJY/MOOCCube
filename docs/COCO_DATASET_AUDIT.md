# COCO Dataset Audit

Date: 2026-06-14

## Source

- Public KG repository: https://github.com/giacoballoccu/CoCo-Educational-Recommendation-Dataset
- Original COCO paper: https://link.springer.com/chapter/10.1007/978-3-319-77712-2_133
- Local public files: `data_raw/COCO_Educational_Recommendation_Dataset/`

The public repository states that this is a preprocessed COCO dataset obtained
by keeping users and items with more than 10 occurrences, with a KG built from
metadata. This is not the full original COCO release.

## Compatibility With Current FAST3 Format

COCO can be mapped into the current processed dataset contract:

- `ratings.txt` -> `stream_data.pkl`
- `i2kg_map.txt` + `kg_final.txt` + `e_map.txt` -> item metadata
- `kg_final` relations -> `relations/course-concept.json`
- course slugs and typed KG labels -> `entities/course.json` and `content_emb.pt`

Recommended relation export:

- Conservative graph: use `belong_to_category` and `related_to_concept` as
  course-concept edges.
- Full metadata graph: additionally include `taught_in_level`,
  `taught_in_language`, and `has_target_audience` with type prefixes.
- Prerequisite graph: do not claim an official prerequisite relation. Use
  behavior-derived prerequisites for experiments, or report any metadata-derived
  curriculum graph as constructed rather than official.

## Risk Assessment

Strengths:

- Course-level items, unlike XES3G5M question-level items.
- Public KG covers every item with typed metadata.
- Concept/category signal is substantially stronger than MOOCCourse.
- Scale is suitable for single-seed triage and later 3-seed main-table runs.

Risks:

- The public KG version is much smaller than the original COCO paper scale.
- Public files do not expose full course descriptions/comments, so content
  embeddings from public data will rely on slugs plus KG labels.
- There is no official prerequisite relation.
- The provided train/valid/test split is per-user time-based, not the strict
  item-cold split used in the current main table.

## Verdict

COCO is a better next candidate than XES3G5M and MOOCCourse for the current
course-aware method, because its item is a course and the metadata KG can
activate the method's structural branch. It is not guaranteed to produce full
SOTA, mainly because text content is weak in the public version and no official
prerequisite edges are available.

Recommended next step: implement a COCO processor and run one strict item-cold
seed for Ours, CCFCRec, DropoutNet, GAR, LightGCL, LightGCN, and BPR. Use this
as a go/no-go gate before any 3-seed run.
