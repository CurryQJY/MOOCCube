Continuation of [[usim-v2-v3-experiment-arc]] after the clean rebuild ([[v32-clean-three-stage-design]]). All seed-2025, MOOCCube, item-macro @10, clean T→G→V3 pipeline (teacher/generator hashes held identical across variants to isolate the changed variable). Run 2026-07-22 to 2026-07-23. Each variant is an isolated script + launcher + tests; nothing overwrites prior results.

**V3.2-Clean (`ckg_rl_usim_v32_clean.py`)** — three-stage clean baseline. Found+fixed a bug: old epoch 0 called rollout with a random actor, so it wasn't a true G(c_i) identity baseline. Fixed so epoch 0 = normalized generator vector (no rollout), epoch≥1 = PPO. `seed2025_identity` selected PPO epoch 15; on C_val PPO beat legit identity by cold N@10 +0.01075 (hot within tolerance). Test: Cold R/N=.2495/.1388, Hot=.2277/.1517, Overall=.2300/.1504. Proves simulator has signal, but below main-table baselines (CGRC cold .2589/.1845, SEMCo overall R .2502) — cannot go on main table. Only seed 2025, main table is 3-seed.

**V3.3 (`rank_distill`)** — replaced generator's vector-MSE with panel rank-distillation (KL to teacher user-affinity distribution over a 48-user panel) + rank-gain PPO reward. FAILED HARD: Cold R/N collapsed to .0798/.0407. Root cause = the RANK GENERATOR, not PPO: it optimized the local 48-user panel KL (0.794→0.602) but wrecked global geometry (all-199k-user KL 0.190→0.258, cosine-to-teacher .234→.100). Cold vector was destroyed before rollout even ran. Hot/overall looked higher only because weak cold vectors stopped competing with hot candidates. Lesson: a local panel KL is a bad global-representation proxy.

**V3.4 (`rank_reward_control`)** — causal control: keep V3.2 vector-only generator (hash-verified identical), ONLY swap PPO reward to V3.3's rank gain. Result: all 15 PPO epochs had negative P_val rank gain → correctly fell back to identity epoch 0 (= exact V3.2 numbers). Diagnosis: 89.5% (128/143) of P_train pseudo-cold items DO have a positive one-step rank-gain action in their 20 legal candidates, but average candidate gain is negative and PPO never learns to pick the good one. So the failure is PPO optimization/identifiability, not an empty action space.

**V3.5 (`action_distill`)** — Counterfactual Action Distillation: enumerate the 20 legal candidate actions per P_train state, compute teacher counterfactual rank gain per action, supervise actor with soft action distribution softmax(gain/τ); PPO only as optional later fine-tune. P-only protocol — strictly NO C_val/C_test in selection (only P_val rank gain gates epochs). FIRST positive result: selected epoch 15, P_val rank gain +0.004718 (V3.4 was all-negative). But only ~7% of the greedy-oracle ceiling (+0.06744), action agreement just 0.239. Frozen-checkpoint test replay (seed-2025 test already seen historically, so diagnostic only): Cold .2501/.1375 (vs V3.2/V3.4 identity +.01358/+.00612), Hot .2283/.1518 (−), Overall .2306/.1503 (overall N −.00152). Improves cold but sacrifices a little hot; overall NDCG still down.

**V3.6 (`global_stable_distill`)** — RAN 2026-07-23 seed-2025, FAILED its own pre-registered viability gate. Two independent ablation switches: (1) expert-trajectory mixing (50/50 teacher-argmax vs actor rollout states) to fix the "only 7% of oracle / 0.239 agreement" multi-step drift; (2) global stability penalty on teacher-score drift at fixed H_G anchor users (calibrated λ=10, anchors=128) to fix the hot/overall regression — λ=10 cut global drift 3.22e-4→1.45e-4 losing only ~4% local gain; λ=30 over-penalizes and inflates END. Result: selected epoch 15, `p_val_rank_gain=+0.006513` (~9.7% of oracle, up from V3.5's 7%), but `p_val_anchor_drift`≈-2.5e-5 (stability penalty WORKED). Gate is composite (`_viability_gate`): needs source-hash + epoch>0 + gain>V3.5's 0.004718 + `train_action_agreement`>V3.5's 0.2388. Gain passed but action_agreement=0.2301 < 0.2388 FAILED → `viability_gate_passed=false`. Per pre-registered protocol, P-only gate fail = NO C_val/C_test read, NO test (`outer_c_val_evaluated=false`, `test_loaded=false`) — this is correct, not incomplete. Full detail in [[v36-result-and-usim-stoploss]].

**Cross-cutting conclusions:**
- USIM is NOT dead but has NOT reached main-method strength. Never write current USIM as the main contribution yet.
- The old strong `.2863/.2098` cold numbers CANNOT go on the main table: audit ([[old-strong-route-audit]]) found no data leak / no warm-checkpoint contamination and it reproduces exactly, BUT its legacy evaluator regenerates a cold item's vector twice (catalog bank vs a separate random positive-sample vector) → not a self-consistent unified ranking metric. NOTE: the main-table overall .1568/.0879 comes from a DIFFERENT run (`significance_per_item_exports/ckg_rl_full`, weak hot from cold-only early-stop), not the .2863 run itself — see [[main-table-evaluator-crack]]. The legacy dual-vector trick inflates COLD only (gated on cold_mask), not overall.
- Core Pareto gap: old route wins cold, clean route (V3.5) wins overall; no version wins both. Old-route-repair seed2025: cold .3062/.2068 but overall only .1454/.0817; V3.5: cold .2501/.1375 but overall .2306/.1503.
- Score fusion (cold-gated MoE of V3.2 + repaired old core) was explicitly rejected as a main method — only acceptable as a low-cost diagnostic; it can't fix the old core's train/inference mismatch and isn't a single-model paper method.
- Discipline enforced throughout: TDD (RED first), hash-verified frozen teacher/generator, test-after-selection manifests, P-only gates, isolated output roots, no overwriting historical results.
